# Стыковка интерфейса и API

Ответственный за backend и интеграцию заменяет реализацию src/api/gateway.ts. Компоненты экранов и Zustand не выполняют fetch напрямую. Контракт адаптера находится в src/contracts/ui.ts: VideoAuditGateway и WorkspaceSnapshot. Сейчас в разработке используется fixtureGateway; production-заглушка возвращает пустой архив и ошибку для действий.

## Передача данных

- load() возвращает записи, события, боксы, каталог типов, токены и состояние обучения. После действия UI повторно вызывает load(), а во время работы опрашивает его раз в 5 секунд.
- BoxView.bbox — нормализованные [x1,y1,x2,y2] от 0 до 1. API использует пиксели исходного кадра: при чтении делить x на video.width, y на video.height; при сохранении умножать обратно. saveBoxes передаёт полный список боксов одного кадра, включая пустой список после удаления всех объектов.
- VideoView.streamUrl и frameUrl ведут на реальные медиа. При отсутствии кадра UI показывает нейтральное состояние; условный кадр находится только в src/dev/fixtureGateway.ts.
- AuditEventView.review отделён от kind: подтверждение человека не меняет исходный тип сигнала. source: human позволяет изменять и удалять только ручные события.
- Собственный тип остаётся draft, пока не подтверждены примеры из 10 разных видео. Одна запись даёт максимум один действующий пример для этого типа; отклонённый пример можно заменить. Backend обязан повторно проверять это правило при публикации. Проверка примеров происходит внутри редактора; они не входят в общую очередь вопросов.
- PipelineView отражает фактические серверные статусы. UI не создаёт новый сигнал или версию модели сам; эти данные возвращает адаптер.
- createToken возвращает полный секрет однократно. Далее load() отдаёт только префикс и метаданные.

## Владение файлами

- UI: src/Screens.tsx, src/Workspace.tsx, src/state, src/contracts, стили, локальные Arc-компоненты и PWA.
- Интеграция: src/api/gateway.ts и backend. При расхождении DTO и UI-моделей преобразование делается в адаптере; контракт экранов меняется после согласования.

Для проверки отображения без backend запускайте pnpm dev: фикстуры доступны только в режиме разработки. Собранная production-версия не подменяет реальные данные.

## Адаптер подключён (Claude2, 17.10)

`src/api/gateway.ts`:
- **`apiGateway`** работает с `/api/v1`, контракт — `backend/docs/API.md`.
- **Источник данных.** В сборке — всегда API. В `pnpm dev` — фикстуры; с `VITE_API=1 pnpm dev` — живой бэкенд через прокси на `localhost:48000`.
- **`load()`** — пять запросов: `/videos`, `/events`, `/event-types`, `/tokens`, `/pipeline`.
- **Боксы:**
  - модели — не чаще кадра в секунду (`/videos/{id}/boxes?step=1`), правки человека — все;
  - кэш по записи до нового анализа или правки, за один опрос догружается не больше 4 записей.

  Если экрану нужны все кадры одной записи, предлагаю добавить в контракт `loadBoxes(videoId)`.
- **Типы событий.**
  - Стандартные — из правил L3 (`rule:…`), предупреждения SOP-чекера (`sop:…`) и шаги процедуры (`step:…`).
  - Собственные — `custom:…`. Публикация на сервере требует подтверждённых примеров из 10 разных записей; одна запись — один действующий пример.
- **Ручные события** — `source: human`, сразу `approved`. Менять и удалять можно только их.
- **`trainModel()`** — сервер отвечает 409 с текстом: обучение запускается на GPU вручную, чтобы не останавливать анализ. `buildDataset()` и `rerunArchive()` работают.

## Боксы над видео (17.10)

- **Режимы `ui.boxMode`** (вместо `overlayVisible`, сохраняются в localStorage):
  - «Нарушения» (по умолчанию) — только боксы классов `AuditEventView.classes` у нарушений и предупреждений, во время которых ±1,5 с идёт воспроизведение; рамка красная или жёлтая, в подписи название; служебные классы (стекло, отражения, дверь, стол) скрыты;
  - «Все» — с чипами классов текущего кадра (`ui.hiddenClasses`);
  - «Скрыть».
- **Редактор кадра** в режиме дообучения всегда показывает все боксы.
- **`classes`** заполняет адаптер (`classesFor` в `src/api/gateway.ts`) по полям события `actor`/`object`/`target` и заголовку правила.
